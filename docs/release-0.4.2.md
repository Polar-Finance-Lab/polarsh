# 0.4.2 — 키체인 한 번 접근 후 작업 상태 유지

2026-10-24

## 선택한 동작

사용자 요청: 키체인 유지, 최초 접근 승인은 허용하지만 사용하는 동안 반복 인증을 피한다.

- 앱 시작 시 기존 Keychain 키로 작업 공간을 한 번 연다. macOS가 요구하는 키체인 접근 승인은 사용자가 처리한다.
- 별도의 LAContext Touch ID / Mac 암호 인증 단계는 빌드에서 제거했다.
- 최초 성공 후 복호화 키는 프로세스 메모리의 Zeroizing 버퍼에 보관한다. 반복 unlock 요청도 해당 키를 재사용하며 Keychain API를 호출하지 않는다.
- 프런트엔드도 중복 unlock 요청을 차단한다. 실패 시 자동 재시도하지 않는다.
- 사용자가 직접 잠그면 메모리 키를 지우고 SSH 세션을 종료한다. 로컬 셸은 유지한다. 앱 종료 후에는 메모리 상태가 유지되지 않는다.
- 호스트 목록/빠른 전환에서 연결된 호스트를 열면 주소·포트·사용자·Bastion 설정이 일치하는 기존 세션으로 이동한다. 편집 버튼은 기존대로 호스트 설정을 연다.
- SSH 서버 인증을 생략하지 않는다. 연결이 끊겼거나 앱을 종료했다면 새 SSH 인증이 필요하며, 비밀번호 자동 저장·자동 재접속은 추가하지 않았다.

## 보존 및 한계

기존 SQLite, Keychain 항목, 접근 제어, 앱 식별자를 유지한다. 키를 로컬 파일로 이전하지 않는다. 자체 서명 테스트도 현재 앱 빌드에 적용하지 않았다.

macOS는 앱 재실행, 재빌드, 키체인 잠금 상태 등에 따라 접근 승인을 다시 요청할 수 있다. 이번 변경은 **현재 프로세스에서 성공한 접근을 재사용**하는 것이며, 앞으로 모든 실행에서 운영체제 인증창이 없어짐을 보장하지 않는다.

## 검증

- Rust: 25 passed, 0 failed, 1 ignored (실제 사용자 Keychain을 건드리는 별도 테스트는 제외). 로그: `logs/polar-0.4.2-tests.log`.
- 새 회귀 테스트: 최초 1회 + 반복 5회 열기에서 키 공급자 호출 1회, 캐시 해제 후 재호출, 캐시 키 불일치·암호문 손상에서 인증 재시도 금지, 키체인 취소·잘못된 키 거부.
- TypeScript/Vite 빌드 통과.
- 사용자 실제 Keychain 승인 및 네이티브 세션 재사용의 최종 확인은 업데이트된 앱 재실행 후 필요하다. 실행 중 작업을 보호하기 위해 기존 앱을 강제 종료하지 않는다.
