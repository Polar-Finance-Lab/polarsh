# 1.0.0 이전 개발 기록

아래 내용은 개발 당시의 상태와 로컬 검증 기록입니다. 현재 사용·빌드 방법은 루트 README를 기준으로 합니다. 실행 로그와 로컬 도구는 저장소에 포함하지 않습니다.

# Polarsh

북극곰을 모티프로 한 **Polarsh 0.11.8**. macOS용 로컬·SSH 통합 터미널 개발 빌드입니다. Tauri 2, React/TypeScript, Rust/russh, xterm.js로 구현했습니다.

호스트와 저장 명령은 암호화해 보관하며, 열 때 macOS 키체인 접근 승인이 필요할 수 있습니다. 승인 후에는 앱 종료 또는 직접 잠그기 전까지 키를 메모리에서 재사용합니다. 별도의 Touch ID 인증은 요청하지 않습니다. SSH 비밀번호와 키 암호는 저장하지 않습니다. 앱 이름은 Polarsh로 변경했지만 기존 저장소와 키체인 식별자는 호환성을 위해 유지합니다.

## 로컬 터미널

앱을 실행하면 저장된 항목의 잠금 해제 없이 기본 로그인 셸이 열립니다. 새 터미널 화면에서 선택한 폴더·셸은 다음 새 탭과 분할에도 적용됩니다. **⌘T**는 독립 탭, **⌘D**는 현재 영역 좌우 분할, **⌘⇧D**는 상하 분할입니다. 탭마다 배치·비율·포커스를 유지하며, 기존 세션은 다시 연결하지 않습니다. 저장된 항목을 잠가도 로컬 세션은 유지됩니다.

탭 막대에서 드래그하면 순서를 바꿉니다. 다른 탭을 터미널 가장자리에 놓으면 분할로 합쳐지고, 여러 영역이 있는 탭은 묶음 그대로 이동합니다. 영역 제목줄을 탭 막대로 끌면 독립 탭으로 분리합니다. ⌘⌥⇧를 누른 채 터미널 본문을 끌어도 영역을 이동할 수 있습니다. 전체 화면 가장자리 24px와 개별 영역 안쪽은 각각 전체/개별 분할 대상으로 구분합니다.

분할 경계 드래그로 크기를 조절하며, 더블클릭으로 해당 경계를 균등 분할합니다. ⌘⌃방향키로 경계 조절, ⌘⌥방향키 또는 ⌘[ / ⌘]로 영역 이동, ⌘← / ⌘→ 또는 ⌘숫자로 탭 이동, ⌘⇧Enter로 현재 영역 확대/복원, ⌘W로 현재 세션을 닫습니다. 탭 닫기는 해당 탭의 모든 세션을 닫으며 여러 세션이 있으면 확인합니다. 앱 전체 세션 한도는 16개입니다. 배치 프리셋은 현재 탭에만 적용합니다.

동작 참고: [iTerm2 General Usage](https://iterm2.com/documentation-general-usage.html), [Profiles](https://iterm2.com/documentation-preferences-profiles-general.html). 별도 macOS 창 생성·창 사이 세션 이동 및 iTerm2 전체 프로필 시스템은 구현 범위에 포함하지 않았습니다.

0.8.0 검증: 탭 트리·분할·로컬 인증 경계 26개 테스트 통과. 브라우저 표시 fixture에서 탭 순서 변경, 탭 합치기, 영역 분리, 분할 탭 전체 이동, 63% 리사이즈 후 다른 탭 왕복 시 비율 보존 확인. 실제 네이티브 키 조합 및 SSH 접속은 이번 변경에서 재검증하지 않았습니다. 로그: logs/polarsh-tabs-tests.log, logs/polarsh-0.8.0-build.log.

## 실행

빌드된 앱: [Polarsh.app](app/src-tauri/target/debug/bundle/macos/Polarsh.app)

```sh
open 'app/src-tauri/target/debug/bundle/macos/Polarsh.app'
```

이미 앱이 열려 있다면 종료 후 다시 열어 최신 빌드를 사용하세요. 앱을 종료하면 로컬 셸과 SSH 세션도 종료됩니다.

Vault 잠금을 해제한 뒤 새 호스트에서 주소·포트·사용자와 인증 방식을 입력합니다. 개인 키는 절대 경로를 입력합니다. 첫 접속 시 서버 지문을 별도 신뢰 경로로 확인한 뒤 승인하세요. 연결된 세션의 **파일** 탭에서 SFTP를 사용합니다.

## 구현 범위

- macOS 로컬 PTY, 로그인 셸, 시작 폴더 선택, Ctrl-C·크기 변경·종료 정리
- LOCAL/SSH 탭 구분, 혼합 화면 분할

- 비밀번호 및 암호화 개인 키 인증, SHA-256 서버 지문 확인
- 다중 터미널 탭, 두 세션 좌우 분할, PTY 입출력·크기 변경, 연결 취소·종료
- 연결된 Bastion을 통한 내부 SSH/SFTP, 다단 경유, 대상 서버 지문 별도 검증
- 호스트·즐겨찾기·그룹·태그·검색, 다중 선택 삭제·그룹 이동·호스트 복제
- 세션별 입력 큐와 출력 흐름 제어
- SQLite 암호화 Vault + macOS Keychain, 기존 평문 호스트 이전
- SFTP 탐색·폴더 생성·다중 파일 업로드·다운로드·진행률·취소
- 암호화 저장 명령, 대상/내용 확인 후 터미널에 넣기

호스트와 저장 명령은 암호화하며, 비밀번호와 키 암호는 저장하지 않습니다. 파일 전송은 기존 파일을 덮어쓰지 않습니다. 로컬/원격 Port Forwarding, 동기화·협업은 아직 없습니다. 서명·공증된 배포판이 아닌 debug 개발 빌드입니다.

## Bastion과 호스트 정리

호스트 등록에서 **배스천 경유**를 선택하고 중계 호스트를 지정합니다. 대상 서버에는 배스천에서 접근 가능한 내부 주소·사용자·인증 정보를 입력합니다. 해당 호스트를 열면 배스천부터 순서대로 연결하며, 각 단계의 인증과 서버 지문을 확인합니다. 기존 연결은 조건이 일치하면 재사용합니다. 부모 연결 종료 시 하위 연결도 종료됩니다.

호스트 카드의 체크박스 또는 **전체 선택**으로 선택하고 **선택 삭제 / 그룹 이동**을 사용합니다. 검색·그룹 전환 시 선택은 해제됩니다. 삭제 확인창은 실제 대상 목록을 표시합니다. 저장된 정보만 삭제하며 열린 세션은 유지합니다. 연결 창의 **호스트 복제** 아이콘은 저장 전 수정할 수 있는 복사본을 만듭니다.

세션 두 개 이상을 연 뒤 **화면 분할**에서 함께 볼 세션을 선택하세요. 각 패널은 독립적으로 입력하며, 도구 모음의 파일·명령 작업은 현재 선택한 탭에 적용됩니다.

## 개발

```sh
open -n 'app/src-tauri/target/debug/bundle/macos/Polarsh.app' --args --demo-hosts
```

```sh

./scripts/app-build

```

스크립트는 프로젝트의 Node 24와 `~/.cargo/bin`을 사용합니다. 프런트엔드만 실행하면 화면 확인은 가능하지만 로컬 셸과 SSH 연결은 Tauri 데스크톱에서만 동작합니다.

## 0.8.1 현재 탭 드래그
선택된 탭을 끌기 시작하면 왼쪽 이웃 탭(없으면 오른쪽)을 배치 대상으로 보여줍니다. 다른 탭 제목 위에 450ms 머물면 해당 탭으로 대상이 전환됩니다. 가장자리에 놓으면 합쳐지고, 중앙이나 바깥에 놓거나 Esc로 취소하면 원래 활성 탭으로 돌아갑니다. 탭 막대에 놓는 순서 변경 동작은 유지합니다.

검증: 수정 전 선택된 탭 드래그 무반응 재현 → 같은 경로로 이웃 탭과 분할 성공. 세 번째 탭 위에 머문 뒤 해당 탭과 합치기 확인. 중앙 드롭 시 원래 탭·배치 복원 확인. 27개 자동 테스트 및 macOS 빌드 통과. 드래그 확인은 실제 컴포넌트를 쓰는 브라우저 fixture에서 수행했으며 네이티브 앱은 세션 보호를 위해 재시작하지 않았습니다.

## 0.9.2 종료 원인 구분과 장애 시험
원격 프로세스가 종료 코드 또는 종료 신호를 보낸 경우, 뒤이어 TCP 연결이 닫혀도 네트워크 장애로 덮어쓰지 않습니다. 프런트엔드 자동 복구는 번역된 오류 문구 대신 백엔드의 `retryable` 상태값을 사용합니다. 정상 로그아웃·로컬 셸 종료·사용자 취소는 자동 재접속 대상이 아닙니다.

격리된 TCP 프록시에서 소켓을 닫지 않고 송수신만 멈추는 시험은 통과했습니다. 실제 keepalive가 약 80초 후 단절을 감지했고 새 연결에서 송수신이 성공했습니다. 실제 macOS 셸 8개의 2분 출력 시험도 통과했습니다: 294회·470,400줄 처리, 종료 정리 포함 125.21초, 셸 프로세스 정리 확인. 이 결과는 수시간 사용이나 전체 앱의 메모리 안정성을 증명하지는 않습니다.

JS 59개와 기본 Rust 30개 테스트가 통과했습니다. 느린 장애/부하 시험 2개는 별도로 실행했으며, 키체인 직접 접근 시험은 실행하지 않았습니다. 기록: logs/polarsh-network-blackhole.log, logs/polarsh-pty-soak.log, logs/polarsh-0.9.2-js-tests.log, logs/polarsh-0.9.2-native-tests.log, logs/polarsh-0.9.2-build.log.

한글 두벌식 입력기 선택 상태는 확인했으나 Computer Use의 키 주입으로 실제 IME 조합 과정을 확인하지 못했습니다. 이를 한글 조합 입력 통과로 간주하지 않습니다. 물리적인 절전/Wi-Fi 전환과 수시간 연속 사용도 별도 검증이 필요합니다. 사용자 네트워크·키체인·입력기 설정은 바꾸지 않았습니다.

## 0.9.1 안정성 점검
재접속 중 원래 탭을 닫으면 진행 중인 연결도 취소하며, 늦게 도착한 성공 응답이 새 탭을 남기지 않도록 수정했습니다. 탭이 16개일 때 끊긴 영역을 교체하는 재접속도 허용합니다. 서버 연결 수 제한은 그대로 유지합니다.

배치 저장 시 닫힌 영역·연결 중인 영역을 제외하고 트리와 포커스를 정리합니다. 명시적으로 비운 작업 공간은 재실행해도 비어 있게 유지하며 저장소 읽기 오류는 기본 시작 흐름으로 처리합니다.

검증: JS 58개 통과(실제 연결 핸들러 100회 재접속 반복 포함). 기존 macOS Rust 테스트 27개 통과, 키체인 직접 접근 테스트 1개는 실행하지 않았습니다. 별도로 실제 PTY 셸 8개 동시 실행을 5회 반복하여 출력 수신과 종료 후 프로세스 정리를 확인했고 통과했습니다. 로그: logs/polarsh-stability-before.log, logs/polarsh-stability-after.log, logs/polarsh-stability-native.log, logs/polarsh-stability-pty-stress.log, logs/polarsh-0.9.1-tests.log, logs/polarsh-0.9.1-build.log.

후속 실제 macOS UI 검증: 별도 식별자 `dev.polarsh.qa.native`의 임시 앱으로 시작 시 키체인 인증 없이 로컬 셸 실행, 3분할·독립 탭·52% 비율 조절, 정상 종료 후 탭/비율/포커스 복원을 확인했습니다. 종료 전 셸 4개가 모두 정리됐으며, 두 번째 재실행에서는 bash와 `/tmp` 시작 폴더 및 선택 탭도 복원됐습니다. 2,000줄 출력 후 프롬프트 복귀, Unicode 한글/이모지 출력, Vim 입력·확대·종료, Ctrl-C 전경 작업 중단도 확인했습니다. 임시 QA 앱은 종료 후 제거했으며 정식 앱을 다시 빌드했습니다.

기록: logs/polarsh-native-ui-qa.json, logs/polarsh-native-restore-ui.txt, logs/polarsh-native-qa-build.log, logs/polarsh-post-native-qa-build.log. 사용자 앱·네트워크·키체인에는 조작을 가하지 않았습니다. 한글 IME 조합 입력, 절전/Wi-Fi 전환, 수시간 연속 사용은 아직 검증하지 않았고 tmux는 미설치로 시험하지 않았습니다.

## 0.9.0 Agent·재접속·작업 공간 복원
- SSH Agent: 인증 방식에서 선택합니다. 앱 환경의 `SSH_AUTH_SOCK`에 연결해 공개 키 최대 6개를 시도하고 서명은 Agent에 맡깁니다. 개인 키는 가져오지 않으며 Agent forwarding 및 OpenSSH 인증서는 이번 범위에 포함하지 않습니다. Agent의 잠금 해제·승인은 Agent 자체 정책에 따릅니다.
- 재접속: 종료된 SSH 영역에서 다시 연결하면 기존 분할 위치·비율로 돌아옵니다. 이전 원격 프로세스나 스크롤백을 복원하는 기능은 아닙니다. 배스천 경로와 서버 지문을 다시 확인합니다. 명시적 네트워크 단절·입력 전송 실패 시 키/Agent 방식은 2초 뒤 자동 복구를 시도합니다. 저장 항목이 열려 있고 다른 연결 작업이 없을 때만 수행하며 호스트별 1분 내 최대 3회입니다. 실패 후 무한 재시도하지 않으며 비밀번호 방식은 직접 다시 입력합니다. 부모가 끊겨 종료된 하위 세션은 개별 재접속할 수 있습니다.
- 작업 공간: 탭 순서·분할 비율·포커스·로컬 시작 폴더/셸을 저장합니다. 다음 실행에서 로컬 셸은 새 프로세스로 열고 SSH는 연결 대기 영역으로 복원합니다. SSH 호스트의 주소·사용자·키 경로·비밀번호·출력은 배치 저장소에 기록하지 않고 호스트 ID만 저장합니다. SSH 재접속 시 저장된 항목을 열어야 하며 시작 시 자동 키체인 인증은 하지 않습니다. 셸 내부의 현재 디렉터리 추적과 원격 프로세스 복원은 포함하지 않습니다.

검증: JS 회귀 53개, Rust SSH 테스트 11개 통과. 사용자 Agent와 분리한 임시 Agent/키로 배스천 경유 SSH·SFTP 인증 성공. 배치 직렬화/유효성 검사/ID 재매핑, 실제 App 재접속 핸들러의 분할 비율 유지와 탭 중복 방지를 검증했습니다. macOS 앱 재실행·절전 복귀를 통한 전체 수동 검증은 수행하지 않았습니다. 로그: logs/polarsh-0.9.0-tests.log, logs/polarsh-0.9.0-ssh-tests.log, logs/polarsh-agent-smoke.log, logs/polarsh-0.9.0-build.log.

## 0.8.5 배스천 자동 순차 연결
저장된 내부 호스트를 열면 필요한 배스천을 바깥쪽부터 연결합니다. 각 서버의 인증 및 지문 확인은 기존 대화상자를 사용합니다. 등록 화면에서 대상 서버에 입력한 비밀번호는 해당 서버에만 전달하며 저장하지 않습니다. 연결된 세션은 주소·사용자·포트·키 설정·지문·부모 세션이 일치할 때 재사용합니다. 이 동작은 끊긴 연결의 자동 재연결과는 별개입니다.

동시에 진행하는 연결 요청을 막고, 인증 재시도에서 실패한 탭을 정리합니다. 취소·최종 실패 시 이번 작업으로 만든 세션을 정리하며 이전부터 연결된 세션은 유지합니다. 순환 경로나 누락된 배스천은 접속 전에 차단합니다.

검증: 실제 App 핸들러에 격리된 IPC/터미널 어댑터를 연결해 순차 인증·중복 요청·세션 재사용·인증 재시도·지문 승인·취소 후 늦은 응답·실패 정리를 확인했습니다. 로컬 합성 SSH 서버의 배스천 SSH/SFTP smoke도 통과했습니다. macOS UI에서 실제 계정으로 수행하는 수동 검증은 이번 변경에 포함하지 않았습니다. 로그: logs/polarsh-auto-route-tests.log, logs/polarsh-auto-route-smoke.log, logs/polarsh-0.8.5-tests.log, logs/polarsh-0.8.5-build.log.

다음 내부 기능: 네트워크 끊김·재접속, 작업 공간 배치 복원, SSH Agent. 이번 버전에는 포함하지 않았습니다.

## 0.11.5 기존 키체인 항목 표시 이름

신규 항목뿐 아니라 기존 항목도 저장 정보 잠금 해제에 성공한 뒤 `Polarsh — 호스트와 저장 명령`으로 표시 이름을 갱신합니다. 기존 서비스·계정·암호화 키와 Vault 경로는 유지합니다. 추가 인증이 필요하면 표시 이름 변경은 건너뛰며 정상 잠금 해제를 실패시키지 않습니다. 첫 승인창에는 아직 이전 이름이 표시될 수 있습니다. 사용자 키체인 항목을 직접 열거나 승인창을 자동 조작하지 않았습니다.

구현 근거: [Apple의 항목 속성 업데이트 문서](https://developer.apple.com/documentation/security/updating-and-deleting-keychain-items), [인증 UI 금지 옵션](https://developer.apple.com/documentation/security/ksecuseauthenticationuifail). 레거시 파일 기반 키체인 호환 경로에서 표시 속성만 업데이트합니다.


## 0.11.6 사이드바 전환 안정화

터미널의 겹침 패널(250px)과 호스트 화면의 메뉴(218–230px)를 공통 240px 고정 사이드바로 통일했습니다. 로고 크기와 상단 위치도 동일합니다. 열린 사이드바는 터미널 옆에 자리를 차지하며, 닫으면 터미널이 전체 폭으로 돌아갑니다. 기존 터미널 탭을 선택해도 사이드바를 자동으로 닫지 않습니다.

브라우저 레이아웃 fixture에서 터미널→호스트 전환 전후 사이드바가 x=0/y=0/폭=240px, 로고 높이=43px, 콘텐츠 시작 x=240px으로 동일함을 확인했습니다. 그룹 30개를 스크롤해도 하단 상태 영역이 고정됩니다. 실제 원격 세션 접속 테스트는 수행하지 않았습니다. 빌드 로그: `logs/polarsh-0.11.6-build.log`.


## 0.11.7 키체인 조회 식별자 전환

0.11.5의 표시 이름 갱신만으로는 기존 항목 접근 시 옛 이름이 남을 수 있어, 실제 키체인 서비스도 `dev.harbor.ssh.vault.v1`에서 `dev.polarsh.vault.v1`으로 전환합니다. 표시 이름은 `Polarsh — 호스트와 저장 명령`입니다. 앱 식별자와 Vault 데이터 경로·AAD는 바꾸지 않습니다.

명시적인 저장 항목 잠금 해제에서만 동작합니다. 먼저 인증 UI 없이 기존 항목의 서비스/라벨을 변경하며, 불가능하면 새 식별자를 우선 조회하고 정확히 항목 없음일 때만 기존 키를 한 번 읽습니다. 기존 Vault 복호화 성공 후 동일 키를 새 식별자로 추가합니다. 복사 경로에서는 기존 항목을 복구용으로 남깁니다. 인증 거부/취소에는 이전 항목으로 재시도하지 않습니다. 전환에 추가 인증은 요구하지 않으며, 실패하면 알림을 표시하고 열린 저장 정보는 유지합니다. 최초 전환 과정에서 기존 이름의 승인창이 한 번 나타날 수 있습니다.

격리된 임시 키체인 항목으로 무인증 rename·키 값 보존·동일 이름 충돌 시 덮어쓰기 방지를 실제 확인했습니다. 임시 항목은 정리했으며 사용자 Vault는 열지 않았습니다. 기록: `logs/polarsh-keychain-migration-integration.log`. 실행 중인 앱에는 재실행 후 적용됩니다.


## 0.11.8 macOS 승인창의 ACL 설명 갱신

실제 사용자 항목에서 서비스와 라벨은 이미 Polarsh였으나, 별도의 ACL 설명 3곳에는 `dev.harbor.ssh.vault.v1`이 남아 있음을 메타데이터 조회로 확인했습니다. 이 설명만 `Polarsh — 호스트와 저장 명령`으로 변경했고, 재조회에서 옛 설명 0개·새 설명 3개를 확인했습니다. 비밀 값은 조회하지 않았습니다. 허용 앱 배열(없음/1개/0개), 인증 플래그와 서명·파티션 ACL은 유지했습니다.

앱에서도 명시적인 Vault 잠금 해제 후 같은 수정을 적용합니다. 추가 인증 UI를 막고 작업 후 기존 프로세스 상호작용 설정을 복원합니다. API 호출은 Vault mutex 안에서 수행됩니다. 신규 항목이나 이미 갱신된 설명은 다시 쓰지 않습니다.

임시 키체인 통합 테스트에서 설명 변경, 키 값 보존, 앱 목록 크기와 인증 플래그 보존, 시스템 ACL 설명 보존을 확인했습니다. 기록: `logs/polarsh-keychain-prompt-integration.log`, `logs/keychain-prompt-repair.log`, `logs/keychain-acl-after.log`. 실제 macOS 승인창을 다시 띄우는 테스트는 수행하지 않았습니다.
