# 0.7.0 — 드래그 도킹 UX 재설계

## 수정한 핵심 문제

현재 보이는 탭을 자신의 영역으로 드래그하면 기존 dockPane의 self-drop 규칙에 의해 항상 무시됐다. 다른 열린 탭이 있어도 사용자가 활성 탭을 가장자리로 끌어 분리할 수 없었다.

planDock은 이 경우 표시되지 않은 열린 탭을 기존 영역에 남기고, 끌고 있는 세션을 옆으로 분리한다. 세션이 하나뿐이거나 4영역 제한에 걸리면 추가 셸/SSH 연결을 만들지 않고 배치를 유지한다.

## 인터랙션

- 커서를 따라다니는 LOCAL/SSH 및 탭 이름표.
- 대상 영역의 좌우·상하 도킹 안내.
- 가장자리에서 최종 크기의 반투명 분할 미리보기와 '놓으면 이 위치에 배치됩니다' 표시.
- 가운데 44% 영역은 중립: 그곳에 놓으면 배치를 바꾸지 않음.
- 분할 영역의 제목도 드래그 핸들로 사용. 확대/제거 버튼은 드래그에서 제외.
- Esc/창 포커스 이탈 시 취소, 최대 4영역, 기존 터미널 인스턴스와 연결 유지.
- 미리보기 계산을 layout effect로 옮겨 화면 반영 전 갱신. 모션 줄이기 설정 시 미리보기 이동 애니메이션 생략.

## 검증

레이아웃 검사 10개 통과 (`logs/polar-0.7.0-layout-tests.log`). 활성 탭 자기 영역 분리, 다른 탭이 없을 때 무동작, 가운데 중립 판정, 네 방향, 4영역 제한을 포함한다.

브라우저 실제 컴포넌트에 포인터 드래그를 실행해 활성 탭 오른쪽 분리, 영역 제목을 끌어 상하로 재배치, 중앙 드롭 시 배치 유지 확인. 드롭 직전 미리보기와 결과 크기 일치: 우측 626×760, 상하 1258×377. 정지된 미리보기 QA도 제공한다.

macOS 검증을 위해 최신 번들의 임시 복사본 `/tmp/Polar Dock QA.app`을 별도 식별자 `dev.harbor.dockqa`로 실행했다. 기존 사용자 앱 프로세스는 유지했다. Keychain을 열지 않고 실제 로컬 셸과 분할 렌더링을 확인했다. 네이티브 드래그 자동화는 도구 파이프 종료와 외부 화면 변경 감지로 완결되지 않아 성공으로 간주하지 않았다. 사용 중일 수 있는 검증 창은 종료하지 않았다. 별도의 배포 앱으로 설치한 것은 아니다.

TypeScript/Vite 및 macOS 0.7.0 번들 빌드 성공: `logs/polar-0.7.0-build.log`. 원래 번들의 서명/데이터는 QA 복사본 변경과 분리했다.
